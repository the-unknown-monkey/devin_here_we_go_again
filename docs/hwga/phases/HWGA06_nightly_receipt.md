# Phase HWGA06: Daily Aggregation & Nightly Unvarnished Receipt

- **Phase ID:** HWGA06
- **Title:** Daily Aggregation & Nightly Unvarnished Receipt
- **Branch:** `main`
- **Status:** Planned (0 / 9 completed)
- **Dependency:** HWGA04 + HWGA05 core data paths
- **Next Phase:** HWGA07
- **Scope:** Deterministic daily context, typed LangGraph workflow, Gemini narrative and validated fallback

## 1. Goal

Turn an actual day of events into an honest, useful, non-shaming receipt while preserving a strict boundary between facts computed by code and narrative generated by Gemini.

## 2. Required Reading

`docs/hwga/trd.md` (deterministic-vs-Gemini rules), `docs/hwga/contracts.md` (DailyContext, Recap, GenerationStatus), `docs/hwga/implementation.md`, `docs/hwga/status.md`, accepted HWGA01 recap contract, and existing event/media/auth code.

## 3. Deliverables

- Deterministic user-local date-window aggregation producing `DailyContext` (contracts.md §2) — counts, intervals, timezone boundary all in code.
- Typed LangGraph state and bounded nodes under `app/agents/graphs/`: load context → validate/normalize → compose candidate narrative → fact guard → persist recap.
- `app/agents/providers/` Gemini adapter: backend-only credentials, timeout/retry limits, structured output schema, no direct DB/file access. **Verify the installed LangGraph/Gemini SDK APIs against the actual package versions before coding — these APIs churn; do not write from memory.**
- Deterministic fallback receipt on provider timeout, quota, malformed output, or schema failure (`GenerationStatus.FALLBACK`).
- Evidence references from narrative/insights to `evidence_event_ids`; reject unsupported quantities, dates, modes, or goal claims.
- Idempotent recap persistence unique on `(user_id, period_type, period_start)`; explicit generation states.
- Flutter nightly receipt view (`lib/features/recaps/`): media references via authenticated ids, honest empty-day state, generation/fallback status.
- Tests: `backend/tests/test_daily_context.py` (timezone boundary, empty/incomplete, missing-data-as-unknown), `test_recap_workflow.py` (schema-invalid output, unsupported-claim rejection, timeout/quota fallback, idempotent retry) with a mocked provider; receipt widget tests.

## 4. LLM Rules

- Pass only `DailyContext` + minimum approved transcript text; no raw media by default.
- The model may summarize/support hypotheses, not compute authoritative counts/durations or diagnose health.
- Missing event data stays unknown; a quiet or resting day is a positive receipt.
- Validate structured output and factual claims in deterministic code before persistence/display.
- Do not swallow provider errors; capture redacted status and use the deterministic fallback.

## 5. Exit Criteria

- Fixture context produces a schema-valid recap; empty, incomplete, timezone-boundary, retry, and provider-failure cases pass named tests.
- Unsupported model claims are rejected or removed by the fact guard.
- Receipt UI check covers success, fallback, empty-day, and no-media states.
