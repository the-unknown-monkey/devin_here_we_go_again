# Phase HWGA06: Daily Aggregation & Nightly Unvarnished Receipt

- **Status:** Planned
- **Dependency:** HWGA04 and HWGA05 core data paths
- **Scope:** Deterministic daily context, typed LangGraph workflow, Gemini narrative and validated fallback

## 1. Goal

Turn an actual day of events into an honest, useful, non-shaming receipt while preserving a strict boundary between facts computed by code and narrative generated by Gemini.

## 2. Deliverables

- Deterministic user-local date-window aggregation into the approved `DailyContext` schema.
- Typed LangGraph state and bounded nodes: load context -> validate/normalize -> compose candidate narrative -> fact guard -> persist recap.
- Gemini provider adapter using backend-only credentials, timeout/retry limits, structured response schema, and no direct DB/file access.
- Deterministic fallback receipt on provider timeout, quota, malformed output, or schema failure.
- Evidence references from narrative/insights to source event ids when practical; reject unsupported quantities, dates, modes, or goal claims.
- Idempotent daily recap persistence and explicit generation states; prevent duplicate recaps under retry.
- Flutter nightly receipt view with sensory media references, honest empty-day state, and generation/fallback status.

## 3. LLM Rules

- Pass only the approved structured context and minimum required transcript text; no raw media by default.
- The model may summarize/support hypotheses, not compute authoritative counts/durations or diagnose health.
- Missing event data stays unknown; a quiet or resting day can be a positive receipt.
- Validate structured output and factual claims in deterministic code before persistence/display.
- Do not swallow provider errors; capture redacted status and use deterministic fallback.

## 4. Exit Criteria

- Fixture context produces a schema-valid recap; empty, incomplete, timezone-boundary, retry, and provider-failure cases have focused checks.
- Unsupported model claims are rejected or removed by the fact guard.
- Focused receipt UI check covers success, fallback, empty-day, and no-media states.
